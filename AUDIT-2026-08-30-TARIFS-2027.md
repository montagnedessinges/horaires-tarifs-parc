# Audit — préparation des horaires et tarifs 2027

Date : 30/08/2026

## Objet

Analyser le comportement actuel lorsque les horaires 2027 sont connus avant les tarifs 2027, lorsque seuls certains tarifs (notamment groupes) sont connus, et identifier l’emplacement réel des tarifs utilisés par le formulaire de devis groupe.

## Constats confirmés dans le code

### 1. Publication d’une saison

Le statut `published` porte actuellement sur toute la saison. Il n’existe pas de statut de publication séparé pour les horaires, les tarifs individuels, les tarifs réduits ou les tarifs groupes.

Conséquence : publier une saison 2027 pour rendre ses horaires consultables peut également rendre ses tarifs 2027 disponibles si la saison contient des tarifs.

### 2. Duplication d’une saison

L’action « Préparer l’année suivante » copie l’intégralité de la saison précédente puis la remet en brouillon. Le tableau `tariffs` contenu dans la saison est donc copié lui aussi.

Risque identifié : si 2027 est préparé par duplication de 2026 et que les tarifs ne sont pas volontairement vidés ou différenciés, les tarifs 2026 peuvent rester présents dans la saison 2027 et être publiés par erreur plus tard.

### 3. Sélection des tarifs côté public

`Parcs_HT_Tariff_Seasons::requested_year()` sélectionne d’abord une saison publiée contenant la date actuelle. À défaut, il retient la saison publiée ayant l’année la plus élevée.

`select_season_tariffs()` remplace ensuite le tableau global `tariffs` par les tarifs de cette saison lorsqu’ils existent.

Il n’existe donc pas encore de mécanisme métier du type : « horaires 2027 visibles mais conserver les tarifs 2026 jusqu’à une date donnée ».

### 4. Catégories tarifaires

Les catégories publiques actuelles sont :

- `individual` : particuliers ;
- `reduced` : tarifs réduits ;
- `groups` : groupes.

Le rendu public construit actuellement les onglets à partir de ces catégories. Le simple fait qu’une catégorie n’ait aucune ligne active n’est pas encore traité comme un statut de publication indépendant de la catégorie.

### 5. Formulaire de devis groupe — emplacement réel des calculs confirmé

Le module « Devis groupe » de l’extension ne calcule pas lui-même les tarifs du formulaire Contact Form 7.

Le code de l’extension :

1. enregistre un shortcode Contact Form 7 dans `settings[quote_page][form_shortcode]` ;
2. vérifie que le shortcode est bien un shortcode `contact-form-7` ;
3. demande à Contact Form 7 de rendre ce formulaire ;
4. ajoute autour du formulaire les titres, messages importants, liens rapides, blocs d’information et accordéons configurés dans l’extension.

L'inspection du WordPress de La Montagne des Singes le 30/08/2026 a permis de localiser les calculs réellement utilisés : ils sont dans le fichier du thème `assets/js/script.js`, donc hors du dépôt de l'extension.

Le bloc historique est conditionné par `#wpcf7-f806-o1`, ce qui identifie le formulaire devis 2026 actuellement utilisé dans ce code.

Tarifs codés dans ce script au moment de l'inspection :

- enfant groupe : `6` € ;
- adulte groupe payant : `8.50` € ;
- personne en situation de handicap : `6` € ;
- accompagnateur : `6` €.

Le calcul accorde actuellement un adulte gratuit par tranche complète de 10 enfants (`Math.floor(nbrenfants / 10)`).

Un ancien bloc supplémentaire existe également pour les classes/champs `nbrenfantsmoins14` et `nbradultemoins14`, avec `6` € et `8.50` €. Ces champs n'apparaissent pas dans le formulaire CF7 fourni pendant l'audit : ne pas les considérer comme actifs sans vérification.

### 6. Formulaires Contact Form 7 connus

Formulaire devis 2026 :

- le JavaScript historique cible l'identifiant numérique `806` via `#wpcf7-f806-o1` ;
- le shortcode CF7 complet n'a pas encore été fourni dans cette conversation ;
- conserver `806` comme identifiant technique observé dans le thème, à revérifier si le formulaire est recréé ou remplacé.

Formulaire devis 2027 FR préparé le 30/08/2026 :

- titre : `Formulaire devis 2027` ;
- shortcode : `[contact-form-7 id="2b9aa49" title="Formulaire devis 2027"]` ;
- identifiant CF7 : `2b9aa49` ;
- il reprend actuellement la même structure de champs que le formulaire 2026 ;
- les tarifs 2027 définitifs ne sont pas encore connus ; le souhait est de pouvoir le préparer avec les tarifs actuels puis remplacer les montants dès validation des tarifs 2027.

Formulaires 2027 EN et DE :

- souhaités mais pas encore créés / identifiants non encore connus au 30/08/2026 ;
- leurs identifiants devront être ajoutés ici dès qu'ils seront communiqués.

### 7. Structure des champs CF7 confirmée

Le formulaire devis fourni contient notamment :

- groupe standard : `nbrenfants`, `nbradultes`, `nbradultgratuit`, `nbradultpayant`, `nbrprixenfants`, `nbrprixadultes`, `totalprixscolaire` ;
- groupe handicap : `nbrpersohandicape`, `nbraccompa`, `totalprixhandicape` ;
- informations organisme/contact et champ obligatoire `visite` pour la date de visite.

Les champs de total sont des champs texte. Les calculs ne sont pas contenus dans la définition CF7 elle-même : le JavaScript du thème les remplit.

## Besoin métier exprimé

Pour 2027, le parc peut connaître et vouloir publier les horaires avant de connaître tous les tarifs.

Cas à gérer :

- horaires 2027 disponibles, tarifs 2027 encore inconnus ;
- tarifs groupes 2027 connus avant les tarifs particuliers ;
- tarifs particuliers 2027 ne devant devenir valides/visibles qu’après la fermeture de la saison 2026 ;
- groupes : le parcours principal reste une demande de devis, avec possibilité de disposer plus tôt des règles/tarifs nécessaires au devis ;
- éviter absolument qu’un tarif 2026 copié lors de la duplication soit présenté comme un tarif 2027.

### Besoin devis multi-années et multilingue

Le visiteur doit pouvoir demander en 2026 un devis pour une visite en 2027. Il ne faut donc pas simplement remplacer automatiquement le formulaire 2026 par le formulaire 2027 à la bascule de saison.

Objectif futur : permettre plusieurs formulaires de devis disponibles simultanément, associés à une année et une langue, par exemple :

- 2026 FR / EN / DE ;
- 2027 FR / EN / DE.

Le visiteur doit pouvoir choisir l'année de son devis et obtenir le formulaire correspondant, même si l'année suivante n'est pas encore la saison active du parc.

Les tarifs d'une même année doivent idéalement être définis une seule fois et partagés par les formulaires FR/EN/DE afin d'éviter trois mises à jour manuelles et les divergences de prix entre langues.

## Évolution à discuter

Prévoir une publication tarifaire indépendante de la publication des horaires, idéalement par catégorie :

- horaires de la saison : brouillon / publié ;
- tarifs particuliers : brouillon / publié + date éventuelle de début d’affichage ;
- tarifs réduits : brouillon / publié + date éventuelle de début d’affichage ;
- tarifs groupes : brouillon / publié + date éventuelle de début d’affichage.

Le moteur public devrait pouvoir afficher les horaires 2027 sans afficher de prix 2027 tant qu’ils ne sont pas publiés.

Si seuls les tarifs groupes sont publiés, l’onglet groupes et/ou le bouton de devis peut être disponible sans exposer les tarifs particuliers encore en brouillon.

Pour les groupes, il faut décider si les tarifs affichés sur la page publique et les tarifs utilisés dans le formulaire CF7 doivent devenir une source de vérité commune. Aujourd’hui ce n’est pas le cas.

### Future évolution du module devis

À concevoir dans une prochaine version de l'extension, sans implémentation automatique à ce stade :

- association année + langue → formulaire CF7 ;
- plusieurs années disponibles simultanément sur la page de devis ;
- choix public de l'année du devis ;
- possibilité de préparer 2027 avant la fin de 2026 ;
- tarifs groupes centralisés par année et réutilisés par les formulaires FR/EN/DE ;
- éviter de dépendre à terme de sélecteurs CF7 codés en dur dans `assets/js/script.js` du thème ;
- prévoir une migration prudente afin de ne pas casser le formulaire 2026 existant.

Cette évolution nécessitera une nouvelle version de l'extension lorsqu'elle sera effectivement développée.

## Suivi du script du thème

Le fichier `assets/js/script.js` appartient au thème WordPress et n'est pas actuellement versionné dans ce dépôt. Toute modification manuelle de ce fichier doit donc être documentée ici avec la date, le motif, les identifiants CF7 concernés et les valeurs tarifaires afin de conserver un historique exploitable.

À chaque création d'un formulaire annuel ou linguistique :

1. noter son titre exact ;
2. noter son shortcode CF7 exact ;
3. noter son identifiant ;
4. noter l'année et la langue ;
5. noter les tarifs auxquels il est relié ;
6. documenter toute modification apportée au JavaScript du thème.

Ne jamais considérer la conversation ChatGPT comme la seule sauvegarde de ces informations.

## Point de sécurité fonctionnelle

Une future évolution doit empêcher qu’une duplication annuelle publie implicitement des tarifs hérités. La copie des tarifs peut rester utile pour préparer un brouillon, mais leur statut de publication doit être réinitialisé et clairement signalé comme « à vérifier » pour la nouvelle saison.
